# XL005 — text-in-aggregated-range

**Severity:** ERROR  
**Confidence:** CERTAIN  
**Requires:** CACHED_VALUES, REF_GRAPH

A string sits inside a range that an aggregate function elsewhere sums. This
names the sum being silently broken.

## Two branches, and they are not the same defect

As with XL004, an Excel error is stored as a string. A `#DIV/0!` inside a
summed range is a broken formula that the aggregate cannot evaluate around,
not a stray label. The `kind` evidence key records which branch fired.

| `kind` | Condition | Message | Remediation |
|---|---|---|---|
| `error` | The value is an Excel error literal, corroborated by the file's own type system | `cached error <value> inside range aggregated by <source>` | Repair the formula that errors; the aggregate cannot evaluate around it |
| `text` | Any other string | `text value inside range aggregated by <source>` | Remove text from the aggregate range or use a separate status column |

## Fixtures

- `kind = "text"` — `Calc!E11` is text inside `SUM(Calc!E10:E11)`.
- `kind = "error"` — a cell inside the same summed range caching `#DIV/0!`.

## Known gap

Aggregates whose bounds do not resolve are skipped, so
`SUM(Table1[Amount])` and `SUM(D:D)` escape this rule entirely: structured and
whole-column references pass through the reference graph with all-`None`
bounds. Recorded in `BACKLOG.md` rather than fixed, because it needs the
reference graph to resolve those forms first.
